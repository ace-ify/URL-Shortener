01

Architecture at a glance

I. AUTH

Dual-tier identity

Humans get HS256 JWTs; machines get sk_live_… keys. Only the SHA-256 hash of a key is ever persisted — the plaintext is shown exactly once.

II. HOT PATH

Sub-ms redirects

Redirect reads the destination from a Redis cache (2h TTL) and returns 307 without touching SQL. DB is only hit on a cache miss.

III. ANALYTICS

Queue + worker

Clicks are RPUSH-ed to a Redis list in <0.2ms. A separate worker BLPOPs, writes to SQL, retries with backoff, then parks poison events in a DLQ.

IV. LIMITS

Two sliding windows

Redis ZSET windows: 30 req/min per IP on public redirects, plus a per-API-key quota read from the database row.

V. DATA

Soft deletes & RBAC

Deletes set deleted_at so analytics survive; reads filter it out. Ownership is enforced on every mutation, with an admin bypass.

VI. OPS

Probes & redaction

/health/live answers instantly; /health/ready pings DB + Redis and 503s on outage. Middleware redacts secrets from logs and stamps X-Process-Time-Ms.

VII. CONTRACT

Versioned & uniform

/v1 carries RFC 8594 Sunset headers; /v2 ships the nested payload. Every failure — including 422s — returns {"error":{"code","message"}}.

VIII. SAFETY

SSRF & alias guards

Blocks localhost, 127.0.0.1, and 169.254.169.254. Vanity aliases are regex-checked and cannot hijack reserved routes.

IX. LAYERS

Routers → services → CRUD

HTTP concerns, business logic, and queries live in separate modules, so the shorten flow is testable without a client.
